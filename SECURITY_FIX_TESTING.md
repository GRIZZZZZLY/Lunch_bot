# 🔒 Исправление утечки конфиденциальных данных - Инструкция по тестированию

## Проблема (ДО исправления)
В dev режиме с `SKIP_TELEGRAM_VALIDATION=true` ВСЕ пользователи получали один и тот же тестовый ID (`555502880`), что приводило к:
- Утечке платёжных данных между пользователями
- Отсутствию конфиденциальности
- Общему профилю для всех

## Решение (ПОСЛЕ исправления)
Теперь даже в dev режиме каждый пользователь получает СВОЙ уникальный Telegram ID:
- ✅ Пропускается только проверка HMAC подписи (для удобства разработки)
- ✅ Реальный `user.id` извлекается из `initData`
- ✅ Каждый пользователь видит ТОЛЬКО свои данные
- ✅ `TEST_USER_ID` используется только как fallback

## Как протестировать

### Тест 1: Два разных пользователя

1. **Пользователь А (например, вы):**
   ```

   - Нажмите Menu

   - Нажмите Menu
   - Перейдите в Профиль
   - Проверьте: поля должны быть ПУСТЫМИ ✅
   - Заполните свои данные:
     * Номер карты: 5555 6666 7777 8888
     * Телефон: +7 (911) 999-88-77
     * Доп. info: "Данные пользователя Б"
   - Нажмите "Сохранить"
   ```

3. **Вернитесь к пользователю А:**
   ```
   - Обновите страницу или откройте профиль заново
   - Проверьте: данные пользователя А должны сохраниться ✅
   - Вы НЕ должны видеть данные пользователя Б ✅
   ```

### Тест 2: Проверка логов backend

Откройте окно backend и проверьте логи:

## Ожидаемые результаты

### ✅ ПРАВИЛЬНО (после исправления):
- Каждый пользователь имеет уникальный `telegramId`
- Платёжные данные изолированы
- Пользователь А видит только свои данные
- Пользователь Б видит только свои данные
- В логах: "authenticated with REAL Telegram ID"

### ❌ НЕПРАВИЛЬНО (если исправление не сработало):
- Все пользователи имеют один `telegramId` (555502880)
- Пользователь Б видит данные пользователя А
- В логах: "fallback test user"

## Что изменилось в коде

### 1. `backend/src/utils/telegram-auth.ts`
Добавлена функция `parseInitDataUnsafe()`:
- Парсит initData БЕЗ валидации подписи
- Извлекает реальный user.id, username, first_name
- Работает ТОЛЬКО в dev режиме

### 2. `backend/src/api/middleware/telegram-auth.ts`
Обновлён `telegramAuthMiddleware`:
- Извлекает реальный Telegram ID из initData
- Создаёт уникального пользователя для каждого
- TEST_USER_ID используется только как fallback

### 3. `backend/src/api/controllers/auth.controller.ts`
Обновлён метод `validateInitData`:
- Использует parseInitDataUnsafe для извлечения реальных данных
- Создаёт пользователя с настоящим ID

## Важные замечания

1. **Production не затронут** - там по-прежнему используется полная валидация с проверкой подписи
2. **Dev режим стал безопаснее** - теперь использует реальные ID даже при SKIP_TELEGRAM_VALIDATION
3. **Удобство сохранено** - не нужно настраивать HMAC ключи для локальной разработки

## Что делать если тест провалился

Если пользователи всё ещё видят общие данные:

1. **Проверьте что backend перезапущен:**
   ```bash
   # Остановите старый процесс
   # Запустите новый: npm run dev
   ```

2. **Проверьте .env файл:**
   ```env
   NODE_ENV=development
   SKIP_TELEGRAM_VALIDATION=true
   # TEST_USER_ID теперь используется только как fallback
   ```

3. **Очистите базу данных (опционально):**
   ```bash
   cd backend
   rm prisma/dev.db
   npx prisma migrate dev
   ```

4. **Проверьте frontend cache:**
   - Откройте в режиме инкогнито (Ctrl + Shift + N)
   - Или очистите кэш (Ctrl + Shift + Delete)
