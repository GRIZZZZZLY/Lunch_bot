# Store Run — состояния экрана (wireframes)

Ширина ориентир 320–430px. `[Status]` — компонент из shared/ui. CTA-зона —
sticky над safe-area. Общие служебные состояния — в конце.

## COLLECTING — участник (не инициатор)

```
── ScreenHeader ─────────────────────────
‹назад(TG)   Пятёрочка у офиса   [Сбор ⏳]
──────────────────────────────────────────
 SUMMARY
   Инициатор: Игорь
   До закрытия сбора            12:41
   ▓▓▓▓▓▓▓░░░  (countdown, живой)
   3 участника · 7 позиций
──────────────────────────────────────────
 МОИ ПОЗИЦИИ (2)
   Молоко 3.2%              ×2   [✎] [🗑]
   «синюю пачку»
   Хлеб бородинский        ×1   [✎] [🗑]
 ─────────
 Игорь · инициатор (3)                (ro)
   Сыр ×1 · Масло ×1 · Кофе ×1
 Аня (2)                              (ro)
   Яблоки ×4 · Кефир ×1
──────────────────────────────────────────
 [ + Добавить позицию ]        ← sticky CTA
```

- `[✎]`→EditStoreItemSheet, `[🗑]`→ConfirmDialog. Только на своих строках.
- Чужие секции — read-only, без иконок.
- **loading**: Skeleton (summary block + 3 text-строки). **empty** (нет позиций):
  EmptyState «Пока пусто — добавьте первым» + кнопка. **error**: ErrorState
  (network/forbidden/notFound) + retry. **pending** (add/delete/edit): кнопка/строка
  disabled + спиннер; повторный сабмит заблокирован.
- **countdown=0, статус COLLECTING**: под summary InlineNotice «Сбор
  закрывается…», refetch; добавление ещё доступно.

## COLLECTING — инициатор

Свои позиции с ✎/🗑, чужие read-only — **без корзины** (фикс B2). Действия без
двух конкурирующих primary:

```
 МОИ ПОЗИЦИИ (2)
   …
   [ + Добавить позицию ]      ← secondary внутри секции «Мои»
──────────────────────────────────────────
 [ Закрыть сбор ]              ← sticky PRIMARY, disabled при 0 позиций
   Отменить закупку            ← destructive secondary → ConfirmDialog
```

- Единственный sticky primary у инициатора — «Закрыть сбор» → ConfirmDialog
  («Закрыть сбор досрочно? Участники больше не смогут добавлять позиции»),
  disabled при пустом списке.
- «Добавить позицию» у инициатора — secondary в секции своих позиций (не primary).
- «Отменить закупку» → ConfirmDialog (destructive), secondary.

## SHOPPING — инициатор (режим «одной рукой»)

```
── ScreenHeader ─────────────────────────
‹назад(TG)   Пятёрочка у офиса  [В магазине 🛒]
──────────────────────────────────────────
 ShoppingProgress
   Обработано 5 из 8
   ▓▓▓▓▓░░░
──────────────────────────────────────────
 ОСТАЛОСЬ (3)
   Молоко 3.2% ×2 · Аня
   «синюю пачку»
   [  Куплено  ] [ Не нашли ]
      ↓ тап «Куплено» — inline-поле в строке:
   Цена за всё (×2), ₽ [____]  [OK]
 ─────────
 КУПЛЕНО (4)
   Сыр · 320 ₽ · Игорь            [⋯]  ← правка цены/статуса inline
 НЕ НАШЛИ (1)
   Кефир · Аня                    [⋯]  ← вернуть в «Куплено» с ценой
──────────────────────────────────────────
 [ Рассчитать ]                ← sticky CTA
   Автоотмена через 2 ч 40 мин, если не рассчитать
```

- Вся строка — крупная цель. Никакого PriceSheet на позицию.
- Поле цены: `inputMode="decimal"`, label «Цена за всё, ₽» или «Цена за всё
  (×N), ₽» при `quantity>1`. **0 допустимо.**
- BOUGHT↔NOT_FOUND переключаемы до settle.
- «Рассчитать»:
  - есть REQUESTED → ConfirmDialog «N позиций без цены не попадут в расчёт.
    Продолжить?» (точное N).
  - есть BOUGHT без цены → settle заблокирован, InlineNotice-critical с числом
    таких позиций (защитно; бэкенд обычно не даёт создать BOUGHT без цены).
  - иначе → сразу settle.
- **loading/error/pending** — как в COLLECTING. **empty** (0 позиций в SHOPPING —
  редко): InlineNotice «Нечего покупать» + «Рассчитать» (создаст 0 долгов).

## SETTLED (read-only)

```
── ScreenHeader ─────────────────────────
‹назад(TG)   Пятёрочка у офиса   [Рассчитано ✓]
──────────────────────────────────────────
 SUMMARY (role-aware)
   — участник:
       Ваша часть: 260 ₽        personalDebtTotal
       Итого закупки: 1 340 ₽   purchasedTotal
   — инициатор:
       Вам должны: 1 020 ₽      receivableTotal
       Ваши покупки: 320 ₽      initiatorOwnTotal (не долг)
       Итого закупки: 1 340 ₽   purchasedTotal
   InlineNotice: Долги созданы и разосланы в Telegram.
──────────────────────────────────────────
 ParticipantBreakdown (из items, клиент; ВСЕ статусы в группе)
   Аня — 440 ₽
     Молоко ×2 · 180 ₽   Куплено
     Кефир               Не нашли      (в сумму не входит)
   Вы — 260 ₽
     …
   Игорь (инициатор) — своё, без долга
     Сыр · 320 ₽   Куплено
──────────────────────────────────────────
   [ На главную ]   ← вторичная кнопка, В КОНЦЕ КОНТЕНТА (не sticky), OQ1
```

- Никаких mutation-кнопок. `refetchInterval:false` (уже в useStoreRun для
  SETTLED). breakdown — клиентский расчёт из `items`: в группу входят
  REQUESTED/BOUGHT/NOT_FOUND, денежный `total` группы — только BOUGHT с `price!=null`.

## CANCELLED (read-only)

```
── ScreenHeader ─────────────────────────
‹назад(TG)   Пятёрочка у офиса   [Отменено ✕]
──────────────────────────────────────────
 SUMMARY (уверенная формулировка — ручного cancel из SHOPPING в API нет)
   shoppingAt == null → «Отменено инициатором»
   shoppingAt != null → «Отменено автоматически: расчёт не был завершён вовремя»
──────────────────────────────────────────
 ПОЗИЦИИ (история, read-only)
   Молоко ×2 · Аня …
──────────────────────────────────────────
   [ На главную ]   ← вторичная кнопка, В КОНЦЕ КОНТЕНТА (не sticky), OQ2
```

- Причина определяется по `shoppingAt` однозначно (`cancellationKind`): ручной
  cancel API разрешает только из COLLECTING (service.ts:398), поэтому наличие
  `shoppingAt` = автоотмена по таймауту. Без «вероятно».

## Общие служебные состояния

- **loading**: `Skeleton` (summary + список), без «карточек».
- **error** раздельно (фикс B4): `network` (retry), `forbidden` 403 «Вы не в этой
  группе» (без retry), `notFound` 404 «Закупка не найдена».
- **некорректный id** в URL: notFound.
- **pending mutation**: инициировавший контрол → disabled + спиннер; блок
  повторного клика; ConfirmDialog в `pending`-режиме (отмена и Escape
  заблокированы) на время settle/cancel/close.
