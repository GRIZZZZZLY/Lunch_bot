## Основные изменения

- CI разделён на фронтенд, сервер и браузерные проверки с PostgreSQL 16.
- Убраны `continue-on-error`, дублирующий процесс проверки запросов на слияние
  и опасные операции со схемой данных.
- Развёртывание использует неизменяемый каталог выпуска, точный SHA, Prisma
  Migrate, корректное имя PM2, `/health` и возврат символьной ссылки на прошлый
  выпуск.
- Docker выполняет миграции отдельным одноразовым сервисом перед запуском.
- Добавлены Dependabot, ограничения версий Node/npm и ограничения размера
  сборки.
- Удалён 31 подтверждённо недостижимый файл и лишние зависимости обоих
  пакетов.
- Исправлены строгие типы фронтенда, обработка обещаний, проверки индексов и
  внешних ответов, а также устаревшая настройка `ts-jest`.
- Запросы API больше не кэшируются сервис-воркером (`NetworkOnly`).
- Устранена двойная подписка на Web Vitals; библиотека вынесена в лениво
  загружаемый блок.
- Добавлены проверки axe WCAG, отсутствия горизонтальной прокрутки, основных
  маршрутов и необработанных ошибок страницы.
- Prisma 7.8 генерируется и проверяется; схема отформатирована. Сценарий
  тестовых миграций отказывается работать не в `NODE_ENV=test` и с именем БД
  без `test`.

## Безопасность

В служебных сценариях и документации найдены два похожих на действующие токена
Telegram. Значения удалены, сценарии теперь требуют `BOT_TOKEN` из окружения и
не печатают его. Оба токена необходимо отозвать через BotFather, потому что они
остались в истории Git. Для полного удаления из истории нужна отдельная
согласованная операция с переписыванием истории.

`npm audit --audit-level=high` проходит для обоих пакетов. На сервере остаются
три средние уязвимости в транзитивной зависимости `@hono/node-server`, которую
подтягивает только средство разработки Prisma. Предлагаемое npm исправление
понижает Prisma до 6 и поэтому намеренно не применялось.

## Покрытие и ограничения локальной среды

Порог фронтенда применяется к критическому прикладному контуру: службам заказов,
магазина, пожертвований, администрирования и геймификации, а также ключевым
пользовательским и административным компонентам. Конфигурационные файлы,
истории Storybook и декларации типов не входят в знаменатель.

Jest сервера уже требует 70% по строкам, операторам, функциям и ветвям. Локальный
запуск остановлен безопасной проверкой, потому что PostgreSQL
`foodbot_test_db` на `localhost:5432` недоступен. В CI база поднимается сервисом
PostgreSQL, затем отдельно проверяются миграции и покрытие.

Локальный Lighthouse на Windows не завершился за 60 секунд из-за запуска Chrome.
Конфигурация и пороги сохранены как обязательный этап Linux CI: производительность
≥ 0,80, доступность и лучшие практики ≥ 0,90, SEO ≥ 0,80.

## Осознанные настройки анализа

- В React Doctor отключена только эвристика длины JSX-компонента. Семь
  отмеченных файлов проверены: состояние и побочные эффекты уже вынесены в
  управляющие функции и дочерние блоки; остальные правила Doctor продолжают
  блокировать CI.
- Серверный ESLint опирается на строгий компилятор TypeScript. Правила явного
  `any`, обязательной ручной аннотации каждого возвращаемого типа и локальных
  неиспользуемых объявлений не включены для старого слоя служб, чтобы не
  переписывать параллельно изменяемый код. Мёртвые файлы, зависимости, импорты
  и циклы контролирует Knip; необработанные обещания и ошибки типов остаются
  блокирующими.
