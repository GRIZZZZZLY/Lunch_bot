# Store Run / SHOPPING — функциональный baseline для Penpot

Статус: Phase 3 завершена функционально (3F, 2026-07-18) — все четыре статуса
Store Run работают на новом feature, legacy удалён, backend/API не менялись.
**Текущий визуал — временный**: композиция, отступы, радиусы и типографика
подлежат замене по утверждённым Penpot-макетам. Логика и DOM-структура —
источник истины. Penpot меняет визуал, но не бизнес-инварианты (§ ограничения).
Терминальные состояния: скриншоты `../frontend-redesign/screenshots/phase-3e/`.

Скриншоты прототипа: `../frontend-redesign/screenshots/phase-3d/`

## Структура экрана (семантический DOM)

```
ScreenHeader        title = storeName, action = Status «В магазине»
└ screen (плоский canvas, вертикальный ритм, разделители)
  ├ [initiator] ShoppingProgress («Обработано X из Y», полоса, «осталось N»)
  ├ [participant] summary «{Инициатор} в магазине» + ShoppingProgress
  ├ секции по статусу: «Осталось» / «Куплено» / «Не нашли»
  │  └ ShoppingItemRow: info (name ×qty / notes / owner) + status line + actions | inline price editor
  ├ InlineNotice critical  — «У N купленных позиций не указана цена» + «Показать»
  ├ InlineNotice info      — автоотмена (текст ниже)
  └ sticky CTA «Рассчитать» (только инициатор, над safe-area)
```

Порядок секций фиксирован продуктово: Осталось → Куплено → Не нашли.
Инициаторский чеклист НЕ группируется по участникам (вопрос инициатора —
«что осталось купить»); владелец — вторичная подпись строки.

## Роли

- **Инициатор**: все контролы строк + settle. 
- **Участник**: read-only; свои позиции первой секцией, «Ваша текущая сумма»
  (= сумма своих BOUGHT price; инициаторские позиции долг не образуют),
  остальные — плоским списком с владельцами; без своих позиций — нейтральный
  текст вместо суммы 0.

## Состояния ShoppingItemRow

| Статус | Отображение | Действия (инициатор) |
|---|---|---|
| REQUESTED | name/qty/notes/owner | «Куплено» (открывает inline-поле цены), «Не нашли» |
| BOUGHT | Status «Куплено» + formatPrice | «Изменить цену» (prefilled), «Не нашли» |
| NOT_FOUND | Status «Не нашли» | «Всё-таки куплено» (inline-поле) |
| inline-editor | label «Цена за всё, ₽» / «Цена за всё (×N), ₽»; inputMode=decimal; Enter=сохранить, Escape=отмена | «Отмена», «Сохранить» |
| pending | вся строка disabled, спиннер на активной кнопке | — |
| error | текст ошибки под полем, raw-ввод сохранён | повторный сабмит доступен |

## Все тексты (копирайт)

- «Обработано {X} из {Y}» · «осталось {N}»
- Секции: «Осталось» · «Куплено» · «Не нашли»
- Кнопки строки: «Куплено» · «Не нашли» · «Изменить цену» · «Всё-таки куплено» · «Отмена» · «Сохранить»
- Поле: «Цена за всё, ₽» | «Цена за всё (×{N}), ₽»; ошибка «Введите цену (0 и больше)»
- CTA: «Рассчитать»
- Confirm (REQUESTED>0): «{N} позиций не обработано» / «Они не попадут в расчёт. Продолжить?» / «Рассчитать без них»
- Critical: «У {N} купленных позиций не указана цена» / «Укажите цену, иначе позиция не попадёт в расчёт.» / «Показать»
- Info: «Завершите расчёт после покупки. Незавершённая закупка может быть отменена автоматически.»
- Участник: «{Имя} в магазине» · «Ваши позиции» · «Остальные позиции» · «Ваша текущая сумма» · «У вас нет позиций в этой закупке.» · «Инициатор рассчитает закупку после магазина.»
- Пусто: «В закупке нет позиций.»

## Ограничения backend (нельзя нарушать дизайном)

- `price` — цена за всю строку; `quantity` информационное; 0 допустим.
- Статус меняет только инициатор в SHOPPING; BOUGHT↔NOT_FOUND до settle;
  возврата в REQUESTED нет.
- REQUESTED не попадают в settle; settle-ответ без breakdown.
- Точный таймаут автоотмены фронту неизвестен — countdown не показывать.
- Серверный `status` — источник истины (переходы экранов только по refetch).

## Временные визуальные решения (заменяемые по Penpot)

- Композиция секций/строк, вертикальный ритм, разделители.
- Кнопки-«таблетки» действий строки (сейчас secondary/ghost Button).
- Размеры/веса типографики, header в Unbounded (alias `--font-head`).
- Полоса прогресса (высота/цвет), стиль InlineNotice, sticky CTA-зона.
