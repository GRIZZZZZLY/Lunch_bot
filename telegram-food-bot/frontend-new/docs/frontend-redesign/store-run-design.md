# Store Run — дизайн-пакет (на утверждение перед Фазой 3)

Основание: [store-run-state-machine.md](store-run-state-machine.md) (семантика бэкенда) + решения владельца от 2026-07-17.
Серверная семантика неприкосновенна: `price` — цена за всю строку; `quantity` информационный; редактирование/удаление — только своих позиций; после `collectUntil` истина — `status` с сервера (лаг крона до 1 мин); REQUESTED не входят в settle; settle response без breakdown — breakdown считается на клиенте из `run.items`.

## 1. Файловая структура

```
src/features/store-run/
├── StoreRunPage.tsx            # маршрутный контейнер: loading/error/403/404 + диспетчер по run.status
├── StoreRunPage.module.css
├── CreateRunSheet.tsx          # перенос rl/CreateStoreRunSheet: пресеты 5/15/30 мин (бэкенд 3..30, фикс B1)
├── components/
│   ├── RunHeader.tsx           # магазин, статус, инициатор, дедлайн + живой таймер (COLLECTING)
│   ├── CollectingView.tsx      # роль-зависимые действия внутри
│   ├── ShoppingView.tsx        # инициатор: чеклист с inline-ценами; участник: read-only прогресс
│   ├── SettledView.tsx         # «ваша часть», итог, client-side breakdown, ссылка на бюджет
│   ├── CancelledView.tsx       # причина по эвристике (shoppingAt), read-only история
│   ├── ItemsByParticipant.tsx  # группировка позиций, секция «Мои позиции» первой
│   ├── ItemRow.tsx             # варианты: collecting-own / collecting-foreign / shopping / readonly
│   ├── InlinePrice.tsx         # раскрывающееся поле цены в строке (inputMode=decimal, автофокус)
│   ├── ItemEditorSheet.tsx     # добавить (bulk до 20) / редактировать свою (name ≤200, qty 1..99, notes ≤500)
│   ├── RunProgress.tsx         # «обработано K из M» + бар (feature-specific, не generic)
│   └── SettleBar.tsx           # sticky «Рассчитать» + confirm при REQUESTED
└── lib/
    ├── selectors.ts            # чистые функции: groupByParticipant, totalAmount, myShare,
    │                           # progress, settleBreakdown, cancelReason
    └── selectors.test.ts
```

Не переносится в фазе 3: `src/services/store-run.service.ts` (API-контракт) и `src/hooks/useStoreRun.ts` (его использует и Home; страница дополнительно подключает уже существующий `useUpdateStoreItem`). Перенос hooks в feature — при разборке Home (фаза 4).

Shared-примитивы (создаются в Phase 2C, только необходимые для Store Run):

```
src/shared/ui/   Button, IconButton, TextField, Status, Skeleton,
                 EmptyState, ErrorState, ConfirmDialog (на базе доступного BottomSheet из 2B)
src/shared/lib/  useCountdown.ts  # серверный timestamp, тик 1 с, коррекция по visibilitychange
```

## 2. Wireframes по статусам (320px, текстовые)

### Создание (CreateRunSheet)

```
── Новая закупка ──────────────────
Магазин
[ Пятёрочка_____________________ ]
Приём заявок
( 5 мин ) ( 15 мин ) (● 30 мин )
[            Создать             ]
```

Пресеты 5/15/30 — внутри лимита бэкенда 3..30 (фикс B1). Ошибка `ACTIVE_RUN_EXISTS` показывается человеческим текстом («У вас уже есть активная закупка»), не тихим фейлом.

### COLLECTING — участник

```
←  Пятёрочка                [СБОР]
   Инициатор: Игорь
   Приём заявок ещё 12:41 · до 14:30
   3 участника · 7 позиций
───────────────────────────────────
Мои позиции (2)
  Молоко 3.2%        ×2    [✎] [🗑]
  «синюю пачку»
  Хлеб бородинский   ×1    [✎] [🗑]
───────────────────────────────────
Игорь · инициатор (3)
  Сыр ×1 · Масло ×1 · Кофе ×1
Аня (2)
  Яблоки ×4 · Кефир ×1
───────────────────────────────────
[       + Добавить позиции       ]
```

- ✎ → ItemEditorSheet (редактирование своей: name/qty/notes; подключается существующий `useUpdateStoreItem`).
- 🗑 → ConfirmDialog «Удалить позицию?».
- Чужие позиции — read-only, без иконок (у всех ролей).
- Empty state: «Пока пусто — добавьте первым» + CTA.
- Таймер 00:00, статус ещё COLLECTING → бейдж «Сбор закрывается…» + форс-refetch; добавление не блокируем (бэкенд примет до перехода), но предупреждаем.

### COLLECTING — инициатор

То же самое (свои позиции — с ✎/🗑, чужие read-only — фикс B2), плюс внизу:

```
[         Закрыть сбор           ]   ← disabled при 0 позиций
       Отменить закупку              ← текстовая danger-кнопка → ConfirmDialog
```

### SHOPPING — инициатор (режим «одной рукой»)

```
←  Пятёрочка           [В МАГАЗИНЕ]
   Обработано 5 из 8   ▓▓▓▓▓░░░
───────────────────────────────────
ОСТАЛОСЬ (3)
  Молоко 3.2% ×2 · Аня
  «синюю пачку»
  [   Куплено   ] [  Не нашли  ]
      ↓ тап «Куплено» раскрывает inline:
  Цена за всё (×2 шт), ₽ [____] [OK]
───────────────────────────────────
КУПЛЕНО (4)
  Сыр · 320 ₽ · Игорь            ›   ← тап = правка цены/статуса
НЕ НАШЛИ (1)
  Кефир · Аня                    ›   ← тап = вернуть в «Куплено» с ценой
───────────────────────────────────
[      Рассчитать (5 из 8)       ]
```

- Вся строка — крупная тап-зона; никакой модалки на каждую позицию.
- Подпись цены при `quantity > 1`: «Цена за всё (×N шт)» — закрывает семантическую ловушку price-за-строку.
- `price = 0` допустим (как в бэкенде).
- BOUGHT↔NOT_FOUND переключаемы до settle (бэкенд разрешает).
- «Рассчитать» при наличии REQUESTED → ConfirmDialog: «3 позиции без цены не попадут в расчёт. Продолжить?».

### SHOPPING — участник (read-only)

```
Игорь в магазине · обработано 5 из 8
Ваши позиции:
  Молоко ×2 — куплено, 180 ₽
  Кефир — не нашли
Закупка отменится автоматически через 2 ч 40 мин,
если расчёт не будет завершён
```

(refetch каждые 15 с уже есть в `useStoreRun`).

### SETTLED (read-only)

```
←  Пятёрочка            [РАССЧИТАНО]
   Ваша часть: 260 ₽                 ← должнику первой строкой
   Итого закупки: 1 340 ₽
   Долги созданы и разосланы в Telegram
───────────────────────────────────
Аня — 440 ₽
  Молоко ×2 · 180 ₽   куплено
  Кефир              не нашли
Игорь (инициатор) — своё, без долга
  Сыр · 320 ₽         куплено
───────────────────────────────────
[           К бюджету            ]
```

Breakdown считается селектором из `run.items` (BOUGHT-цены по `userId`; позиции инициатора помечаются «своё, без долга»). Инвалидация `['budget']` при settle уже есть.

### CANCELLED (read-only)

```
←  Пятёрочка             [ОТМЕНЕНО]
   Отменено инициатором
   ── либо (shoppingAt != null): ──
   Отменено автоматически: расчёт
   не был завершён за 3 часа
───────────────────────────────────
Позиции (история, read-only) …
───────────────────────────────────
[     Создать новую закупку      ]   ← только бывшему инициатору
```

### Все статусы

- loading → Skeleton; ошибка сети → ErrorState с «Повторить»; 403 → «Вы не состоите в этой группе»; 404 → «Закупка не найдена» (сейчас всё склеено в одно).
- Мутации: disabled + спиннер на время запроса, повторный клик невозможен.

## 3. Матрица действий (UI = бэкенд)

| Действие | COLLECTING иниц. | COLLECTING участник | SHOPPING иниц. | SHOPPING участник | SETTLED | CANCELLED |
|---|---|---|---|---|---|---|
| Добавить позиции (bulk ≤20) | ✅ | ✅ | — | — | — | — |
| Редактировать позицию | только свои | только свои | — | — | — | — |
| Удалить позицию (+confirm) | только свои | только свои | — | — | — | — |
| «Куплено» + цена ≥ 0 (inline) | — | — | ✅ | — | — | — |
| «Не нашли» | — | — | ✅ | — | — | — |
| Правка BOUGHT↔NOT_FOUND / цены | — | — | ✅ до settle | — | — | — |
| Закрыть сбор | ✅ (disabled при 0) | — | — | — | — | — |
| Отменить (+confirm) | ✅ | — | — | — | — | — |
| Рассчитать (+confirm при REQUESTED) | — | — | ✅ | — | — | — |
| Просмотр | все члены группы | все | все | все | все | все |

Отличия от текущего UI: убрана корзина инициатора на чужих позициях (B2 — бэкенд 403), добавлено редактирование своих (мёртвый `useUpdateStoreItem`), подтверждения на delete/cancel, inline-цена вместо per-item модалки.

## 5. Тестовые сценарии

Unit — `selectors.test.ts`:
- группировка по участникам, «Мои позиции» первыми;
- `totalAmount` = Σ price по BOUGHT (quantity игнорируется — как в бэкенде);
- `myShare` — позиции инициатора исключены из долга;
- `progress` K из M;
- `settleBreakdown` по участникам из `run.items`;
- `cancelReason`: `shoppingAt != null` → авто-отмена, иначе — инициатором.

Unit — `useCountdown`:
- тик раз в секунду, достижение нуля;
- коррекция после `visibilitychange` (вкладка спала — время верное);
- считает от серверного timestamp, не от локального старта.

RTL — компонентные:
1. Участник, COLLECTING: bulk-добавление, редактирование своей, удаление через confirm; на чужих нет ✎/🗑.
2. Инициатор, COLLECTING: нет 🗑 на чужих (B2); «Закрыть сбор» disabled при 0 позиций; cancel только через confirm.
3. Таймер истёк, статус COLLECTING → «Сбор закрывается…», refetch вызван.
4. Инициатор, SHOPPING: inline «Куплено» + цена (включая 0), «Не нашли», обратное переключение, прогресс обновляется, подпись «за всё (×N)» при qty > 1.
5. Участник, SHOPPING: контролов нет, прогресс и свои позиции видны.
6. Settle: при REQUESTED — confirm с точным числом; без REQUESTED — без предупреждения; успех → инвалидация `['budget']`.
7. SETTLED: read-only, «Ваша часть» должнику, breakdown, инициатору «своё, без долга».
8. CANCELLED: обе причины, read-only.
9. Ошибки: network → ErrorState + Retry (рефетч); 403 и 404 — разные сообщения.
10. CreateRunSheet: пресеты 5/15/30; `ACTIVE_RUN_EXISTS` → понятная ошибка (B1).
11. Дубль-мутации: повторный клик settle/close во время запроса невозможен (disabled).
12. Smoke: длинные русские названия без переполнения, 320px без горизонтального скролла.
