## 🚀 ЗАПУСК ПРОЕКТА

### Вариант 1: Docker (Рекомендуется)

```bash
# 1. Перейти в папку проекта
cd C:\BOT_V2\telegram-food-bot

# 2. Запустить все сервисы
docker-compose up -d

# 3. Проверить статус
docker-compose ps

# 4. Смотреть логи
docker-compose logs -f
```

### Вариант 2: Локально (для разработки)

```bash
# 1. Запустить только базу данных
docker-compose -f docker-compose.dev.yml up -d

# 2. Backend (в отдельном терминале)
cd backend
npm install
npm run dev

# 3. Frontend (в отдельном терминале)
cd frontend
npm install
npm run dev
```

## ❌ TROUBLESHOOTING

### Проблема 1: Бот не отвечает

**Симптомы:** Команды не работают

**Решения:**
```bash
# 1. Проверить, запущен ли backend
docker-compose ps backend

# 2. Проверить логи
docker-compose logs backend

# 3. Проверить токен
docker-compose exec backend printenv BOT_TOKEN

# 4. Перезапустить
docker-compose restart backend
```

### Проблема 2: База данных не подключается

**Симптомы:** Ошибка "Can't reach database server"

**Решения:**
```bash
# 1. Проверить, запущен ли postgres
docker-compose ps postgres

# 2. Применить миграции
docker-compose exec backend npx prisma migrate dev --name init

# 3. Или создать таблицы
docker-compose exec backend npx prisma db push

# 4. Проверить подключение
docker-compose exec backend npx prisma db pull
```

### Проблема 3: Уведомление не приходит

**Симптомы:** Рулетка работает, но личное сообщение не пришло

**Причины и решения:**

1. **Пользователь не начал диалог с ботом**
   - Решение: Отправьте `/start` боту в личных сообщениях

2. **Пользователь заблокировал бота**
   - Решение: Разблокируйте бота в настройках Telegram

3. **Notification service не инициализирован**
   - Проверка: `docker-compose logs backend | grep "Notification service initialized"`
   - Решение: Перезапустите backend

4. **Ошибка при отправке**
   - Проверка: `docker-compose logs backend | grep "Failed to send winner notification"`
   - Решение: Проверьте логи ошибок

### Проблема 4: Frontend не открывается

**Симптомы:** Mini App не загружается

**Решения:**
```bash
# 1. Проверить статус
docker-compose ps frontend

# 2. Проверить порт
curl http://localhost:5173

# 3. Проверить логи
docker-compose logs frontend

# 4. Пересобрать
docker-compose build --no-cache frontend
docker-compose up -d frontend
```

### Проблема 5: Порты заняты

**Симптомы:** "Port already in use"

**Решения:**
```bash
# Windows - проверить занятые порты
netstat -ano | findstr :3001
netstat -ano | findstr :5173
netstat -ano | findstr :5432

# Убить процесс по PID
taskkill /PID <PID> /F

# Или изменить порты в docker-compose.yml
```
