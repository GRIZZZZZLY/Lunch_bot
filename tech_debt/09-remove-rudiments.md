## 9.1 Семь no-op шимов инициализации бота

`grep "@deprecated No-op: bot is now accessed"` → **7 вхождений**:

| Файл | Строка |
|---|---|
| `backend/src/services/budget.service.ts` | 16 |
| `backend/src/services/multi-category-responsible.service.ts` | 18 |
| `backend/src/services/order-calculation.service.ts` | 9 |
| `backend/src/services/recurring-poll.service.ts` | 44 |
| `backend/src/services/poll.service.ts` | 59 |
| `backend/src/services/poll.service.extensions.ts` | 17 |
| `backend/src/services/responsible.service.ts` | 13 |

Все имеют вид:

```ts
/** @deprecated No-op: bot is now accessed via the shared singleton */
export function initializePollServiceBot(_bot: unknown): void {}
```

Это остатки миграции на `bot/bot-instance.ts`. Пустая экспортируемая функция —
худший вид рудимента: она выглядит рабочей точкой расширения и её будут
вызывать. Заметьте, что `poll.service.ts` и `poll.service.extensions.ts`
экспортируют функцию **с одним и тем же именем** `initializePollServiceBot` —
кто из них попадёт в импорт, зависит от порядка импортов у вызывающего.

**Вызывающие — их меньше, чем кажется.** Продакшен-вызов ровно один:
`backend/src/index.ts:63` (`initializePollServiceBot(bot)`, импорт на строке 13,
из `./services/poll.service.extensions`). Остальные шесть шимов **не вызываются
вообще**. Плюс есть тест, который держит шим живым:
`backend/src/__tests__/unit/services/poll.service.extensions.test.ts:407` —
`expect(() => initializePollServiceBot({})).not.toThrow()` (импорт на строке 12).

**Почему `knip` это не поймал** (вопрос закрыт, доисследование не нужно):

1. В скрипте нет нужного включения —
   `knip --include files,dependencies,unlisted,unresolved,catalog,cycles`.
   **`exports` в списке отсутствует**, то есть knip в этом репозитории
   структурно не ищет неиспользуемые экспорты.
2. В `backend/knip.json` в `entry` перечислен `"src/**/*.test.ts"` при
   `"includeEntryExports": true` — значит импорт из теста удерживает
   продакшен-экспорт «живым» даже после добавления `exports`.

Отсюда следствие: **критерий «knip зелёный» ничего не доказывает** ни в этой,
ни в других задачах. Добавьте `exports` в `--include` — и тогда knip станет
инструментом, а не украшением. Пункт `"src/**/*.test.ts"` в `entry` при этом
придётся пересмотреть отдельно (он там, вероятно, чтобы knip не жаловался на
тестовые файлы как на недостижимые — есть более узкие способы это выразить).

**Что делать:** удалить вызов из `index.ts`, удалить тест на строке 407,
удалить семь экспортов.

**Перед удалением проверьте баррели.** Вывод «шесть шимов не вызываются» получен
grep'ом по имени функции, а реэкспорт звёздочкой (`export * from './budget.service'`
в каком-нибудь `services/index.ts`) таким grep'ом не ловится. Один
`grep -rn "export \*" backend/src` закрывает вопрос.

**Подводный камень:** удалять вызов, тест и объявления **одним** коммитом.
Если удалить объявление раньше вызова — сборка упадёт.

## 9.3 Deprecated-методы `VoteService`

```
backend/src/services/vote.service.ts:493  // Обновление существующего голоса (DEPRECATED - используйте createVote + deleteVote)
backend/src/services/vote.service.ts:768  // Получение голоса пользователя (DEPRECATED - используйте getUserVotes)
```

**Что делать:** проверить вызывающих (включая `bot/handlers/`, `poll.controller`,
тесты). Если вызывающих нет — удалить. Если есть — перевести на замену,
указанную в комментарии, и удалить. Не оставлять «на всякий случай»: помеченный
DEPRECATED и при этом вызываемый метод — это не рудимент, а второй способ
делать одно и то же, то есть источник расхождения.

**Подводный камень:** `updateVote` может быть единственным путём, который
сохраняет `id` голоса. Пара `createVote + deleteVote` меняет id, и если где-то
на id голоса построена идемпотентность или SSE-дедупликация — поведение
изменится. Проверьте перед удалением.

## 9.5 Мёртвые экспорты в `.design-sync/`

14 файлов в `frontend-new/.design-sync/` **отслеживаются git'ом** и содержат
26 экспортов без единого импортёра (`ds-theme-root.tsx::DSThemeRoot`,
`previews/*.tsx` — `Basic`, `Variants`, `States`, `WithError`, …). Последний
коммит — 2026-07-18. Это ~221 строка.

Соседние каталоги `frontend-new/ds-bundle/` и `frontend-new/.ds-sync/`
**не** отслеживаются git'ом — это локальный инструментарий, их трогать не надо.

**Внимание: каталог неоднороден, одной командой его удалять нельзя.** Из
14 отслеживаемых файлов мёртвый код — это `previews/*.tsx` (9 файлов) и
`ds-theme-root.tsx`. Остальные четыре — `config.json`, `conventions.md`,
`NOTES.md`, `ds-fonts.css` — это **конфигурация и соглашения** инструмента
design-sync, а не мёртвые экспорты.

**Что делать:** удалить из git 10 файлов с мёртвыми экспортами (`previews/` и
`ds-theme-root.tsx`). Четыре файла конфигурации — отдельное решение: если
инструмент используется локально, они остаются (или уезжают в `.gitignore`,
как соседние `ds-bundle/` и `.ds-sync/`). Вариант «подключить превью к
storybook» здесь не рассматриваем: это проект, а не уборка.
