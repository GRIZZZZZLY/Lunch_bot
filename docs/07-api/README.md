# Обзор REST API

Сервер публикует API под префиксом `/api`. Точный перечень маршрутов находится
в `backend/src/api/routes/`; этот документ описывает границы и общие правила, а
не дублирует каждую схему запроса.

## Аутентификация

1. Mini App отправляет Telegram `initData` в `POST /api/auth/validate`.
2. Сервер проверяет подпись и срок действия.
3. Клиент получает JWT.
4. Последующие запросы используют:

```http
Authorization: Bearer <jwt>
Content-Type: application/json
```

Не передавайте JWT и `initData` в адресе запроса.

## Основные области

| Префикс | Назначение |
|---|---|
| `/api/auth` | вход, текущий пользователь, обновление сессии |
| `/api/user` | профиль и группы пользователя |
| `/api/menu` | меню группы |
| `/api/suggestions` | предложения блюд |
| `/api/polls` и `/api/votes` | голосования и голоса |
| `/api/store-runs` | групповые закупки |
| `/api/groups/:groupId/stores` | справочник магазинов группы |
| `/api/user/item-presets` | личный список товаров пользователя |
| `/api/budget` | долги, оплаты и стоимость заказа |
| `/api/recurring` | расписания повторяющихся голосований |
| `/api/admin` | административные операции |
| `/api/gamification` и `/api/seasons` | опыт, достижения и сезоны |
| `/api/insights` | агрегированная статистика |
| `/api/donations` | Telegram Stars |

Состояние сервиса:

- `GET /health` — общее состояние;
- `GET /health/live` — процесс жив;
- `GET /health/ready` — зависимости готовы.

## Групповой контекст

Большинство предметных запросов выполняется в контексте `groupId`. Сервер
обязан проверять членство и роль пользователя; одного значения, присланного
клиентом, недостаточно для авторизации.

## Изменяющие запросы

Критические операции поддерживают `Idempotency-Key`. Клиент должен повторять
тот же ключ при повторной отправке одного действия и создавать новый ключ для
нового действия.

## Ошибки

Новые обработчики используют `application/problem+json` и возвращают
машиночитаемый `code`. Для совместимости часть ответов также содержит
`success: false` и `error`.

## Поток обновлений

Голосование обновляется через защищённый поток
`GET /api/polls/:pollId/stream`. JWT передаётся в заголовке `Authorization`.

## Источник истины

- регистрация областей: `backend/src/api/server.ts`;
- маршруты: `backend/src/api/routes/`;
- контроллеры: `backend/src/api/controllers/`;
- клиентские вызовы: `frontend-new/src/services/`.
