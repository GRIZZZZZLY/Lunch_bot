# Остаточные риски и решения владельца

Неисправленных критических или высоких рисков в выпускаемом runtime не
обнаружено. Ниже средние/низкие риски, которые либо требуют продуктового
решения, либо несовместимого изменения.

| Уровень | Риск | Почему оставлен | Что сделать |
|---|---|---|---|
| низкий | `npm audit` помечает React Router 7.18.1 из-за `GHSA-qwww-vcr4-c8h2` | предупреждение относится только к экспериментальным серверным компонентам; Rocket Lunch использует декларативный `BrowserRouter`, а 7.18.1 исправляет применимые к `Link/useNavigate` проблемы предыдущих версий | до появления исправленной версии 7 запускать `npm run audit:prod`: исключение ограничено одним номером версии и одним предупреждением; не включать серверные компоненты |
| средний | сообщения о СОЗДАНИИ долга идут мимо очереди уведомлений | через `outbox_events` проходят все переходы долга — отметка, отмена отметки, подтверждение, отмена подтверждения, массовое подтверждение, магазинные отметка и подтверждение — и итог «Все оплатили». Мимо очереди остались два сообщения о создании долга: при расчёте заказа (`order-calculation.service.ts`) и при закрытии магазинного забега (`store-run-budget.service.ts`, `notifyStoreRunSettled`). Их сбой не проваливает расчёт, но повторной доставки нет. Причина: в этих сообщениях реквизиты получателя, которые в БД хранятся зашифрованными, и класть их в `payload` задания открытым текстом нельзя; кроме того, при расчёте заказа бот правит сообщение «Ожидаем расчёт» и записывает его `message_id` в долг | перевести, храня в задании только id долга и собирая текст с реквизитами в момент отправки; обработчику — записывать `debtMessageId` после доставки |
| средний | резервные копии базы лежат на том же сервере, что и сама база | ежедневная копия (systemd `telegram-food-bot-backup-db`, 14 копий в `~/backups/rocket-lunch`) проверена восстановлением 2026-09-24: все ключевые таблицы совпали, восстановление 3,6 с. Но при потере VPS копии пропадут вместе с базой; `scripts/backup-postgres-offsite.sh` (restic) на сервер не установлен | установить restic и хранилище вне сервера, включить `backup-postgres-offsite.sh` по расписанию; RPO сейчас — сутки |
| низкий | за накоплением очереди уведомлений следит только внешний сборщик | показатели выведены: `GET /api/metrics/prometheus` (нужны `ENABLE_OPERATIONS_API=true` и заголовок `X-Operations-Secret`) отдаёт `food_bot_outbox_pending`, `food_bot_outbox_retrying`, `food_bot_outbox_failed` и `food_bot_outbox_oldest_pending_age_seconds`. Те же числа есть в JSON `GET /api/metrics`. Правила оповещения не настроены | настроить оповещение по возрасту самого старого ожидающего задания: количество под нагрузкой всегда больше нуля, а возраст растёт только когда доставка встала |
| низкий | гарантия доставки — «хотя бы один раз», не «ровно один» | между отправкой в Telegram и записью результата в БД остаётся окно: падение процесса в нём приведёт к повторной отправке того же сообщения | риск уменьшен сохранением `sentMessageId`; править существующее сообщение вместо отправки нового там, где это уместно |
| средний | backup/restore не прогнан с Docker в этой среде | Docker/WSL недоступны; проверены синтаксис и безопасный алгоритм, но не реальный контейнер | до выпуска выполнить backup и пробный restore на копии той же версии PostgreSQL |
| средний | не выполнен реальный E2E Telegram webhook/Stars | нет разрешения и боевых/предпродакшн секретов | закрытый staging: неверный/верный webhook secret, повтор update, precheckout, duplicate successful_payment |
| средний | часовой пояс расписаний общий для процесса | текущая модель не хранит TZ на группу | подтвердить `TZ`; при разных регионах добавить IANA timezone в Group |
| средний | 24 high backend и 19 high frontend в dev tools | они в Jest/ESLint/Storybook/Lighthouse/glob и не устанавливаются в runtime; предлагаемые npm исправления несовместимы или ошибочно понижают основные инструменты | изолировать CI, не запускать его с production secrets; обновлять цепочки по мере совместимых релизов |
| низкий | CSP разрешает `style-src 'unsafe-inline'` | текущие библиотеки и inline styles зависят от этого | перейти на nonce/hash для стилей или вынести inline styles; `script-src` уже без unsafe-inline |
| низкий | совместимые дубли `/polls/*` и `/votes/*`, `/polls/` и `/history` | их удаление может сломать старый клиент | добавить телеметрию использования и удалить в следующей основной версии |
| низкий | нет единого строгого Zod-описания каждого старого query/path параметра | критические домены проверяют диапазоны в контроллерах/сервисах, но часть старых read-only фильтров использует ручной разбор | постепенно вынести параметры всех маршрутов в общие схемы |
| низкий | Redis при долгом сбое пишет повторяющиеся сетевые ошибки | это полезно для диагностики, но может создавать шум | ограничить одинаковые сообщения в сборщике логов и оповещать по readiness |

## Обязательные решения пользователя до выпуска

1. Указать production/staging домены, режим webhook/polling, `TRUST_PROXY` и TZ.
2. Указать место резервных копий, срок хранения, RPO/RTO и ответственного за
   проверку восстановления.
3. Указать канал оповещений и дежурного.
4. Разрешить и предоставить отдельные staging-секреты для реального Telegram/
   Stars E2E.
5. Решить, переводить ли на очередь сообщения о создании долга (см. таблицу выше):
   для этого реквизиты придётся расшифровывать в момент отправки, а не при постановке.

## Условия «не выпускать»

- `REDIS_ENABLED` не true или readiness не 200;
- wildcard/http в CORS production;
- нет проверенной резервной копии и пробного восстановления;
- миграции имеют pending/failed;
- CI красный или `npm run audit:prod` не проходит;
- Operations API включён без отдельного секрета и регламента;
- неизвестен предыдущий образ/план отката;
- реальные секреты находятся в файле образа или репозитории.
