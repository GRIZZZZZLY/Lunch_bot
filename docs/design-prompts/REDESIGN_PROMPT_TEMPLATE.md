## Что это

**Rocket Lunch** — Telegram Mini App для организации групповых обедов. Коллеги голосуют за блюдо, один человек выбирается ответственным, через СБП собирает деньги. Цель — простая UX повседневного использования.

**Стек:** React 18 + TypeScript + Vite + Tailwind + собственные CSS-переменные. Открывается **только внутри Telegram** на мобильном (ширина 430 px max). Темы переключаются по `themeParams.color_scheme` от Telegram.

**Прикладываю:**
1. **~48 скриншотов** всех экранов приложения в светлой и тёмной темах. Каждый файл: `<page>_<state>_<theme>.png`.
2. **Дизайн-срез кодовой базы** (папка `design-upload/` через «Attach codebase»): все стили, страницы и визуально-важные компоненты. Бизнес-логика, тесты, сервисы — исключены.

**Опирайтесь на реальный код**, не предлагайте гипотетические классы/переменные. Палитра — в `src/styles/index.css` и `tailwind.config.js`. Применение тёмной темы — через класс `.dark` на `<html>` (см. `App.tsx`).

## Задача — полировка, НЕ редизайн

Мне **не** нужен новый визуальный язык. Структуру экранов, набор компонентов, иконки и общий tone-of-voice — сохранить. Задача — **отшлифовать то, что уже есть**:

### 1. Вёрстка (приоритет)

Пройдитесь по каждому скриншоту и укажите проблемы вёрстки:

- Перекрытия (bottom nav поверх контента, z-index конфликты).
- Неконсистентные отступы (padding/margin между блоками).
- Выравнивание (иконки vs текст, кнопки в рядах).
- Переносы текста в кнопках/pills.
- Широкие/узкие карточки относительно 430px viewport.
- Слишком мелкие/крупные tap-зоны (Telegram требует ≥44×44 px).
- Неаккуратные тени и радиусы.

**Пример проблемы, которую я заметил сам:**
- На `stats_personal_light` нижняя навигация наезжает на контент карточек — z-index или padding-bottom scrollable области.
- На `profile_admin_light` плавающая кнопка «Поддержать» перекрывает важный текст внизу.

### 2. Цветовые схемы — light и dark

Проверьте обе темы на всех скриншотах:

- **Контрастность:** текст vs фон, особенно в pills, badges и secondary text (AA минимум: 4.5:1 для body, 3:1 для large).
- **Согласованность палитры:** один и тот же семантический цвет (например, оранжевый primary) должен читаться одинаково в обоих режимах.
- **Фоновые переходы:** карточки не должны «теряться» на фоне — должен быть чёткий визуальный разрыв (border или shadow).
- **Акценты:** сейчас оранжевый `#d86a2c` — проверить, не давит ли он в dark-режиме.
- **Статусные цвета:** красный (долг), жёлтый (ожидание), зелёный (оплачено) — читабельны в обоих режимах?

**Текущая палитра (из `index.css`):**
```css
/* light */
--surface: #fffdf9;  --surface-2: #f6efe5;
--ink: #2b2118;  --ink-2: #6b5d4f;  --ink-3: #9c8b79;
--pri: #d86a2c;  --peach-400: #ff9d66;  --peach-500: #d86a2c;
--lav-400: #a78bfa;  --mint-400: #34d399;  --coral-400: #f87171;
--butter-400: #f4c15d;

/* dark */
--surface: #2a1f1a;  --surface-2: #1e1612;
--ink: #f4ece3;  --ink-2: #c9b7a4;  --ink-3: #8a7867;
--pri: #ff9d66;
```

Если какие-то переменные стоит переопределить — предложите конкретные hex'ы с обоснованием.

### 3. Типографика

- Проверить размеры шрифта для мобильного (минимум 13px для secondary, 15-16px для body).
- Line-height в длинных блоках (сейчас местами слишком сжато).
- Единообразие: цифры везде моноширинные (`JetBrains Mono`) или везде Inter tabular-nums?
- Hero-заголовки (`Доброе утро, Иван!`) — можно сделать чуть крупнее и жирнее для emotional impact.

### 4. Мелочи (если заметите)

- Emoji-иконки vs Lucide-иконки — согласованность.
- Стиль pills/badges (скругления, фон, размер).
- Состояние hover/active/disabled у кнопок и тайлов.

## Что НЕ делать

- Не предлагать новые экраны, новые фичи, новый flow.
- Не заменять иконки целиком на кастомный иконсет (оставить lucide + emoji).
- Не переделывать компоненты в другой UI-kit (shadcn, Radix и т.д.) — мы на своих CSS-классах.
- Не трогать структуру bottom navigation, tab'ы на Stats, 6 сценариев Budget Widget.
- Не увлекаться анимациями — максимум лёгкие fade/slide, без framer-motion оркестра.

## Формат ответа

Для каждого замечания дайте **конкретику, опираясь на реальный код**:
- **Скрин:** `menu_with-items_light.png`
- **Код:** `src/components/menu/DishCard.tsx:42` или `src/styles/index.css` (переменная `--peach-500`)
- **Что не так:** «Карточка блюда — цена сливается с ценником, коричневый ₽280 на бежевом плохо читается»
- **Решение:** конкретный diff или патч CSS. Например:
  ```css
  /* index.css */
  --peach-500: #b84d12;  /* было #d86a2c — поднять контраст на бежевом фоне */
  ```
  или:
  ```tsx
  /* DishCard.tsx:42 */
  - <span className="text-peach-500 font-semibold">₽{price}</span>
  + <span className="text-peach-600 font-bold tabular-nums">₽{price}</span>
  ```

В конце — **сводная таблица приоритетов**: блокеры / важные / nice-to-have.

## Технические детали (на случай, если понадобятся)

- Viewport 430 × 932 px (iPhone 14 Pro). Скриншоты в @2x (860 × 1864).
- Тёмная тема включается классом `.dark` на `<html>`.
- Telegram WebApp API: `MainButton` рендерится НЕ нами — внизу приходит native-bar. Для нашего layout это значит: **резервируем ~64 px safe-area внизу**.
- Шрифты: Inter (UI), JetBrains Mono (числа).
- Готовые CSS-классы: см. `index.css` — `surface`, `pri`, градиенты `--g-peach/lav/sage/sky/butter/coral/mint/rose`.
