# 👥 Тестирование с командой через Dev Build

## ✅ Да, можно тестировать с другими пользователями!

Dev build (`start-dev.ps1` или `start-prod-dev.ps1`) полностью поддерживает **многопользовательское тестирование** через Telegram.

---

## 🎯 Как это работает

### Архитектура:

```
[Пользователь 1] ──┐
                   │
[Пользователь 2] ──┤
                   │
[Пользователь N] ──┴──> [@rocket_lunch_bot] ──> [ngrok HTTPS] ──> [Ваш ПК]
                                                                      │
                                                                      ├─ Backend (3001)
                                                                      ├─ Frontend (5173)
                                                                      └─ Proxy (8080)
```

**Все пользователи подключаются к ОДНОМУ боту** (`@rocket_lunch_bot`), который работает на вашем компьютере через ngrok туннель.

---

## 🚀 Пошаговая инструкция

### Шаг 1: Запустите dev build

```powershell
cd telegram-food-bot
.\start-dev.ps1
# или
.\start-prod-dev.ps1
```

### Шаг 2: Настройте ngrok URL

В окне 5 (URL Updater):
1. Скопируйте HTTPS URL из окна 4 (ngrok)
2. Вставьте и нажмите Enter
3. Дождитесь автоматической настройки

### Шаг 3: Пригласите тестировщиков

Попросите других пользователей:

1. **Открыть бота в Telegram:**
   - Найти `@rocket_lunch_bot`
   - Нажать `Start` или `/start`

2. **Открыть WebApp:**
   - Нажать кнопку `Menu` внизу
   - Или команду `/app`

3. **Готово!** Они подключены к вашему dev серверу 🎉

---

## ✨ Что могут делать тестировщики

### ✅ Полный функционал:

- **Регистрация и авторизация**
  - Автоматическая регистрация при первом входе
  - Данные сохраняются в вашей локальной БД

- **Просмотр и добавление меню**
  - Видят все блюда
  - Могут добавлять новые (если админы)

- **Участие в голосованиях**
  - Создание голосований (если админы)
  - Голосование за блюда
  - Просмотр результатов

- **Групповые чаты**
  - Добавьте бота в группу
  - Все команды работают (если у них права)

- **Уведомления**
  - Получают напоминания о голосованиях
  - Результаты рулетки

## ⚙️ Настройка прав доступа

### Сделать пользователя администратором:

1. Узнайте Telegram ID пользователя:
   - Попросите его написать `/start` боту
   - В логах backend (окно 1) найдите: `User: { id: 123456789, ... }`

2. Откройте `backend/.env`:
   ```bash
   # Добавьте ID через запятую
   ADMIN_USER_IDS=555502880,123456789,987654321
   ```

3. Перезапустите backend (закройте окно 1 и запустите `start-dev.ps1` снова)

Теперь этот пользователь может:
- Создавать голосования (`/startpoll`)
- Управлять меню
- Видеть админ-панель в WebApp

## 🚨 Ограничения и нюансы

### 1. ngrok ограничения (бесплатный план):

❌ **40 подключений/минуту**
- Для небольшой команды (5-10 человек) - достаточно
- Для больших тестов - может быть медленно

❌ **URL меняется при перезапуске**
- Каждый раз при запуске `start-dev.ps1` - новый URL
- Нужно обновлять через URL Updater
- Бот автоматически обновит Menu button

✅ **Решение:** ngrok платный план ($8/мес):
```powershell
ngrok config add-authtoken YOUR_AUTH_TOKEN
ngrok http 8080 --domain=your-domain.ngrok-free.app
```

---

### 2. Безопасность (SKIP_TELEGRAM_VALIDATION=true)

⚠️ **Снижена проверка безопасности:**
- Пропускается валидация Telegram подписи
- Теоретически, кто-то может подделать запрос

✅ **Но для dev это нормально:**
- Используется только для тестирования
- Не в production
- Локальная БД

---

### 3. Производительность

⚠️ **Ваш ПК - сервер:**
- Все запросы идут через ваш компьютер
- Если ПК выключен - бот не работает
- Скорость зависит от вашего интернета

⚠️ **ngrok добавляет задержку:**
- ~50-200ms дополнительной задержки
- Для тестирования - приемлемо

---

### 4. База данных

✅ **Все пользователи в одной БД:**
- `backend/prisma/dev.db` (SQLite)
- Можете просмотреть через Prisma Studio
- Можете сбросить: удалите `dev.db` и запустите `npx prisma db push`

## 🔧 Troubleshooting

### Тестировщик не может открыть WebApp

**Причины:**
1. Старый ngrok URL (вы перезапустили dev build)
2. Bot menu button не обновлен

**Решение:**
- Перезапустите URL Updater (окно 5)
- Попросите тестировщика перезапустить бота (`/start`)

---

### "Invalid hash" ошибка

**Причина:** `SKIP_TELEGRAM_VALIDATION=false` в `.env`

**Решение:**
```bash
# backend/.env
SKIP_TELEGRAM_VALIDATION=true
```

Перезапустите backend.

---

### Тестировщик не видит обновления

**Причина:** Нет автоматической синхронизации

**Решение:**
Попросите его:
1. Потянуть страницу вниз (Pull to Refresh)
2. Или перезапустить WebApp

---

### ngrok: "429 Too Many Requests"

**Причина:** Превышен лимит бесплатного плана

**Решение:**
1. Подождите минуту
2. Или используйте ngrok платный план
3. Или ограничьте количество тестировщиков
